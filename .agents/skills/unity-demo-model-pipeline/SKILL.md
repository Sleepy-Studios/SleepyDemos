# Unity Demo Model Pipeline

## 核心原则

- 先读取真实玩法代码、Prefab、配置、物理挂点、资源命名规则和既有模型契约，再提出建模方案。
- 把“玩法需要什么”翻译成模型层级、尺寸、坐标、Pivot、材质槽、动画、碰撞代理和挂点，不从截图或名称臆测接口。
- 在建模前向用户确认所有会改变模型结构或运行契约的选择；未确认时继续做只读盘点，不开始建模。
- 视觉模型与物理语义分离。不得因换皮移动施力点、挂点、碰撞代理或控制轴，除非用户明确批准并同步修改契约和测试。
- 严格区分 DCC 源坐标、FBX 导出坐标和 Unity 运行坐标。源模型先遵循 Blender 自身已确认的前向/上方向，再由固定导出设置和 Unity Importer 转换；不得在建模时凭感觉套用 Unity 轴，也不得用长期 AssetPostprocessor 或运行时代码掩盖源模型航向错误。
- 在完整装配前先做最小轴向门禁：临时导出一个包含根、前向标记和关键可动层级的候选 FBX，在真实 Unity Importer 下验证前后、左右、上下、局部旋转轴和镜头光轴。门禁失败时回到源模型或导出设置修正，不继续叠加补偿。
- 保留源文件和导出物，记录 Blender/Unity 版本与导出参数。没有源文件授权、Blender 能力或目标 Unity 实例时，明确暂停在对应门禁。

## 工作流

1. **盘点 Demo**
   - 阅读项目 Agent 规则、资源命名规范、目标模块文档和 runbook。
   - 搜索模型、Prefab、Builder、Importer、材质、Collider、动画、挂点和契约测试的真实引用。
   - 区分视觉节点、物理节点、运行时组件和编辑期生成物。

2. **形成需求并确认**
   - 按 [建模需求模板](references/modeling-requirements.md)填写需求。
   - 明确新建、换皮或结构扩展；列出保持不变的运行契约。
   - 把所有高影响未知项集中交给用户确认。尺寸、Blender 源前向/上方向、Unity 目标前向/上方向、Pivot、骨骼、可动结构、材质槽和交付路径未锁定时不得进入 Blender。

3. **检查工具和源资产**
   - 检查可用的 Blender MCP、CLI 或 GUI 控制能力，不假设固定版本、端口或安装路径。
   - 打开前保留用户源文件；需要覆写时先建立可恢复副本。
   - 确认模型、贴图和参考图的许可允许进入目标项目。

4. **在 Blender 建模**
   - 使用米制和已确认的 Blender 原生前向/上方向；用明确的机头标记、左右象限和可动节点局部轴复核，而不是只看对象欧拉角。
   - 在导出对象上应用 Rotation/Scale，禁止负缩放；父子层级应用 Transform 后必须重新检查子节点局部矩阵，特别是云台、相机、轮子和机械臂。
   - 让 Pivot 对齐真实旋转、施力、铰链或挂载语义。
   - 复用相同 Mesh，不为对称部件复制无意义资源；只导出运行时需要的对象。
   - 不导出预览相机、灯光、地面、标注和辅助对象，除非契约明确要求。

5. **导出与交付**
   - 按目标项目约定导出 FBX，显式记录 Blender 版本、Forward、Up、Apply Transform、单位、动画和可见对象策略。不要把某篇教程的参数当成跨版本真理，必须以目标 Unity 的真实导入结果为准。
   - 先输出到非生产路径，保持生产 FBX 与 `.meta` 不变；真实 Unity 轴向门禁通过后才替换正式 FBX。若候选路径会绕开或命中 Importer/Postprocessor，必须明确记录差异。
   - 对源侧导出物与项目内副本计算 SHA-256；需要相同交付物时必须一致。
   - 不直接覆盖用户已完成的材质、Prefab 或源文件引用。

6. **导入 Unity 并装配**
   - 确认当前 Unity 实例和项目路径后再操作。
   - 检查 ModelImporter 的 Scale、轴转换、动画、BlendShape、Camera、Light、Readable 和材质策略；同时检查根节点及每个被脚本引用的子节点是否残留 90°/180°包装旋转或负缩放。
   - 用左右输入、上下输入和中立姿态分别对照模型朝向与 Game 画面；只看 Scene Gizmo 或只看画面都不足以证明轴向正确。
   - 优先运行项目既有 Builder/装配入口；不另建并行生成体系。
   - 保持 Prefab 脚本 GUID、序列化引用、物理挂点和资源地址。

7. **验证并交付**
   - 按 [Unity 导入验收清单](references/unity-import-validation.md)执行静态、自动化和视觉验收。
   - 运行目标 Demo 直接相关的最小 Unity Test Runner 范围；不使用 dotnet/msbuild 验证 Unity 工程。
   - 对比层级、材质、旋转方向、Collider、动画、阴影和运行时行为；截图记录需要人工判断的结果。
   - 报告实际验证范围、未执行项、源文件位置、导出参数和剩余风险。

## Demo 契约路由

- 如果目标 Demo 存在机器可读或文档化模型契约，先读取并将其作为硬门禁。
- 如果代码、Builder、测试和文档对同一规则给出不同值，停止建模，先确定唯一来源并修正漂移。
- 如果没有契约，先从真实调用点形成候选需求并交由用户确认；不得把本 Skill 的示例值当作项目规则。
