# 任务前上下文验证

收到非平凡的实现任务时，在动手写代码之前，先自查上下文是否充分。

## 核心原则

**能自己查的不要问用户。** 代码、Prefab、配置表都能自己读（用 Read / Unity Skills / Grep），只有"运行时行为"和"业务意图"才需要问用户。

## 自查流程

1. **读代码**：目标文件、参考文件、调用入口、ViewComponent
2. **读 Prefab**（如果涉及 UI）：用 Unity Skills 或直接读 .prefab 文件，确认层级结构等
3. **读调用方**：Grep或lsp 找到所有调用入口，确认改动是否需要保持向后兼容
4. **识别缺失信息**：以上都读完后，如果还有不确定的，才问用户

## 什么时候问用户

- 业务意图不清晰（功能边界、交互细节）
- 框架约定（代码和 Prefab 里都看不出来的隐性规则）

## 注意

- 简单任务不需要验证流程
- 问用户时简洁直接，不要变成问卷
