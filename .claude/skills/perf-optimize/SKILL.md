# 证据驱动的运行时优化

采集与报告操作使用 [unity-performance](../unity-performance/SKILL.md)，分配调用链使用 [unity-profiler-gc](../unity-profiler-gc/SKILL.md)。代码规则、验证和层次以项目文档为准。

1. 读目标流程与所有调用方，确认 Self、Total、Calls、GC 和发生阶段。用户提供的单帧数字是观察，不预设热点。
2. 判断是重复计算、算法、引擎调用、持续分配还是等待。峰刺读具体帧及相邻帧；CPU 工作、GC 回收、Shader 首次使用、资源加载、音频、Canvas 和 Present 分开归因。
3. 沿真实调用链找到根因。在现有公共实现处修复共享问题，避免各调用方加补丁；复用项目已有组件、工具和缓存。
4. 优先减少无效调用和未变化数据的重算；缓存须有明确失效、唤醒和生命周期。保持所有可见更新和玩法精度，不以降低分辨率、隐藏内容或可见降频交付性能收益。
5. 逐项记录证据、收益空间、行为风险和最小方案。跳过无实际收益或复杂度不合理的候选，不以改动数量证明完成。
6. 先验证正确性，再以相同阶段与设置重复配对采样；报告分位、周期事件与波动，不凭单个峰值宣布改善。

一般性优化模式不是规则：不假设每个 foreach 都分配、不把所有属性访问都缓存，也不照搬其它 Unity 版本的 API 成本。新能力只有稳定复用价值才进入 Core；Demo 业务仍在 Hotfix。
