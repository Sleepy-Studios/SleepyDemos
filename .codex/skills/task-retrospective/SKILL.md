# 任务复盘技能

## 触发条件

用户在任务完成后主动说出以下关键词之一：
- "任务完成了"、"总结回顾"、"复盘任务"、"总结下这个任务"、"回顾下"

## 输出格式

生成一份 Markdown 复盘报告，结构如下：

```markdown
# [任务标题]

> 日期：YYYY-MM-DD
> 涉及文件：[列出修改的文件路径]

## 1. 初始提问

> 用户原始提问的精简还原（保留核心意图，去掉冗余）

## 2. 迭代过程

| 轮次 | 问题/症状 | 根因 | 修复方式 |
|------|---------|------|---------|
| 1 | ... | ... | ... |
| 2 | ... | ... | ... |

> 如果一次到位没有迭代，写"✅ 一次到位，无迭代"

## 3. 最终效果

简述最终实现了什么功能，改了哪些文件，核心算法/逻辑是什么。

## 4. 最优提示词

如果用户第一次提问就提供以下信息，可以一次到位：

\```
[完整的、可直接复制使用的提示词模板]
\```

### 为什么这些信息缺一不可

| 信息 | 缺失时的后果 |
|------|------------|
| ... | ... |

## 5. 经验沉淀

- 【通用规律】：从本次任务中提炼的、可复用到其他任务的经验
- 【项目特有】：本项目特有的踩坑点（如框架约定、Prefab 约定等）
```

## 保存规则

1. 保存路径：`E:\Vibe_Coding\提问与优化记录\`
2. 文件名格式：`YYYY-MM-DD_[任务关键词].md`（如 `2026-05-14_FishDetailTips箭头定位.md`）
3. 如果路径不存在或用户要求换路径，先问用户确认
4. 保存后告知用户文件路径

## 与 pre-task-validation 规则的联动

复盘报告中的"最优提示词"和"经验沉淀"部分，如果发现了 `.claude/rules/pre-task-validation.md` 中没覆盖到的验证项，主动建议用户是否要更新该规则。

## 注意事项

- 复盘要客观，不要美化迭代过程
- "最优提示词"必须是可直接复制粘贴使用的完整文本，不是抽象描述
- 如果任务一次到位没有迭代，也要总结为什么能一次成功（哪些上下文给对了）
- 迭代表格只记录"走了弯路"的轮次，正常的确认沟通不算迭代
