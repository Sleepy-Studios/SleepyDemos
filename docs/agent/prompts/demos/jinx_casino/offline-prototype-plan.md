更新日期：2026-10-02。用户要求先完成P1–P4，再回头处理联机。此顺序覆盖原始Goal中“P0互联网验收通过后才铺开内容”的阶段门槛；完整交付与验收范围保持不变。

## 实施顺序与交付门槛

| 阶段 | 离线交付 | 退出证据 |
|---|---|---|
| P1 | 街角幸运厅、三机台、标准局阶段额度与倒计时、商店和首批事件、失败及返回Hub | 从正式入口完成新局、下注、事件、购物/推进或失败、退出；规则与生命周期测试、运行截图 |
| P2 | 四区通道与推进、三结局、人数配置、检查点及三个本地存档槽 | 四区可达、结局条件明确且三结局可达；保存恢复不重复结算、场景清理正确 |
| P3 | 17款小游戏、24道具、20事件、单人辅助、练习/无尽、成长图鉴 | 每项可操作并产生对应规则/场景行为，有取消/恢复；新增玩法与经济/库存/事件回归 |
| P4 | 原创卡通角色、四区、17机台、道具、双端UI、音效、结局及战绩演出 | 资源已落地且正确绑定、无正式体验占位资源；场景/UI/演出实际查看，双端内容包可构建 |
| 后置联网 | Fusion AOT桥接、私人房间、同步移动/经济/事件、权威交接与重连 | SDK/App ID就绪后实际PC/Android不同网络混合房间验证；不以离线模拟通过替代 |
| P5–P6 | 跨平台打磨及最终源码/资源/ZIP/APK/报告 | 原定多人数、两台Android真机、连续30分钟与目标硬件性能、互联网验收全部完成 |

每阶段交付实际可运行版本与验证记录后继续下一阶段。内容开发期间使用显式离线单人和NPC辅助，保留权威命令/完整快照边界；之后接入网络时不能由客户端自行决定资金或重新开奖。

## 规则与宿主

小游戏引擎只处理规则、随机状态、操作和整数计时，不依赖UI或物理。冒险聚合统一拥有共享钱包、阶段、库存、事件、小游戏和已处理请求；金额锁定、最终扣款、奖励与消耗只提交一次。特别是盲拍只扣成交价，关闭操作面板不能撤销已提交结果。

场景宿主负责输入、机台交互、区域门、NPC、整蛊和演出；界面通过现有Core Canvas、View与MvcBind装配。场景只有一个本地主Camera和AudioListener，联网角色后续不带相机。全部Demo资源保持在`Assets/LoadResources/Demos/jinx_casino/`，不新增生产或测试程序集。

整蛊最大3秒，同目标5秒保护；概率/收益变化在下一笔投入前展示。单人协作玩法提供明确助手或替代操作，不用统一随机开奖代替17款不同玩法。道具和事件必须有具体执行行为，名称、目录或文案不能作为功能完成证据。

## 验证边界

使用现有Tests.EditMode/Tests.PlayMode，通过Unity Test Runner串行运行直接相关范围。Editor编译、自动化流程、视觉查看、双端Player构建和真机/互联网分别记录。原有P0离线验证产物保留；后续版本不能沿用P0通过记录来声称新内容已验收。
