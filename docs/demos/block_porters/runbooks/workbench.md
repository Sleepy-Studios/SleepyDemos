# 小小搬豆工图片关卡工作台

## 入口与资料

非 Play 模式打开 `Tools/SleepyDemos/小小搬豆工/关卡编辑器`。工具不重建场景、UI、模型或字体；这些资源直接维护已保存资产，绑定使用 UIBind。

单图用“导入单图”，多图可拖入项目/外部 PNG、JPG 或选择“批量目录”。原图副本与配方在 `Assets/Settings/BlockPorters/`；正式导出在 `Assets/LoadResources/Demos/block_porters/Data/`。关卡集默认为 `Data/LevelCatalog.asset`，也可显式选择其他关卡集作为导出目标。

## 单图流程

1. 导入图片或打开已有 `BlockPortersRecipe`。选择 16、24、32 或自定义不超过 32 的宽高。
2. 设置归一化裁剪、保持宽高比与透明度阈值。默认保留不透明背景；需要时启用“剔除指定背景色”，或转换后用擦除画笔手工修正。
3. 选简单/普通/困难预设，调整色数预算、近色合并强度、最小色差、近色组数与种子。预设预算为 5/8/12，不强制凑满色数；近色辅助为 0/1/2 组。额外改色默认 10%，自动处理不改变占用轮廓。
4. 点击“重新转换图片”。后台顺序执行像素化、Lab 聚类和队列候选生成。转换会替换手工修正并重置锁定区。
5. 比较原图、像素化、调整结果。用涂色、填充、拾色、锁定、擦除画笔修正；色号行选择画笔色，合并会删除原色号并更新网格。新增色号后画笔局部涂色即为手工拆色。操作支持 Unity Undo/Redo。
6. 点击“仅重新安排队伍”保留图案与锁定区，重新生成队列；也可直接编辑五列数组（兼容旧四列）的色号、人数和顺序。Color 从 0 开始，人数 1–8，各色人数必须等于方块数。
7. 点击“分析当前队列”。检查可解状态、参考解、占位选择、等待、堵塞和固定种子模拟结果。`Unknown` 是预算耗尽/取消，不是已可解；难度不达标时调整内容后重试，工具不自动降档。
8. 当前版本通过可解性和目标难度后点击“导出已验证关卡并加入关卡集”。同一配方后续导出更新原资产、保留 GUID；新资产追加关卡集，顺序直接编辑关卡集 Inspector。保存配方后下次可继续编辑，但需重新分析才能导出。

后台计算期间继续编辑会使结果过期。切换配方、Undo/Redo 或取消同样不会写回旧结果。改变尺寸后必须重新转换，不能将旧数组当作新尺寸解释。锁定保护人工编辑；“仅安排队伍”不会重新转换色表。

## 批量流程

先在当前配方设置尺寸、难度和预算，再拖入多图或选目录。工具逐图导入、转换、生成、验证，达标才导出；单图失败继续处理下一张，保留失败配方并在结果列表说明原因。可取消当前和剩余批量，已成功导出的文件保留，取消结果不写回。关闭窗口会取消计算，不会在窗口关闭后写入资产。

## 默认内容与验收

关卡集先保留 `Level1`–`Level5` 教学内容，随后包含 `StrategyEasy`、`StrategyNormal`、`StrategyHard`，三者由同一自制图和保存配方生成。固定种子模拟报告只是辅助筛选，玩法是否有趣、图案是否可辨仍须实际试玩。

新生成和仅重新安排队伍默认输出五列，旧四列配方仍可打开、分析及导出，游戏第五列为空。正式八关已迁移为五列，网格、色表和 GUID 保留；对应导出配方同步队列并推进内容版本，必须重新分析才能再导出。迁移时的五列难度报告位于 `Assets/Settings/BlockPorters/FiveColumnMigration.json`，其中普通／困难指标都是固定种子策略回放结果，不代表玩家通过率。参考解始终使用五个免费任务位，不调用广告解锁。

通过正式 `AppEntrance → Hub → 小小搬豆工` 进入。每列显示当前队和随后三队预览；无目标的成员只占逻辑任务位。通过下一关遍历关卡集，检查多人抬砖、交付、重开和返回清理。

在 Unity Test Runner 运行直接相关类：`BlockPortersWorkbenchTests`、`BlockPortersBatchTests`、`BlockPortersAssetTests`、`BlockPortersSessionTests`、`BlockPortersFlowTests`。生成关卡运行回放测试会加速共享虚拟钟，仍通过正式控制器创建角色、抬砖和回收；它不代替自然速度手感与手机性能验证。截图在 `Library/BlockPorters/Evidence/`，不提交。
