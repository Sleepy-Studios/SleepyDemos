# 纸艺卡丁车 2026-10-13 性能收口

本页记录本次已完成的 Editor 采样、正式 CPU/GC 分析与结论。工具用法见[Editor 性能维护](editor-performance.md)。原始 `.data`、逐段报告、截图、聚合 JSON 和哈希校验清单保存在本机 `ValidationArtifacts~/KagitKartPerformance/20261013/`；此目录不纳入 Git。

## 当前条件与比较边界

八场正常驾驶统一使用 1920×1080、renderScale 1、实际 MSAA 1、场景 SMAA High、后处理开启、八车、120 Hz 规则、正常动态、同一份业务与公共设置。Game View 的 VSync 在采样中临时关闭，质量档的 VSyncCount 仍为 1；Editor 全局音频静音为 true，业务设置的 Muted 为 false。Profiler 关闭 Deep Profile 和 Editor 自身采样；普通窗口不启用 GC 调用栈，诊断窗口单独启用。每场分段录制，截图与报告计算均在录制窗口外。

Main 场景制作默认使用 SMAA High，用户显式 AA 选择仍由公共设置覆盖。SMAA 与原作目标的 4×MSAA 算法不同，不能声称像素等价。四章最终截图已检查纸艺角色、赛道、阴影、纸纹、HUD 与配色；左右触控按钮实图核对为 160×140，自动油门与方向键点击区域分离，Pressed 为朱红底/米白箭头；设置页选中项有朱红底色。截图不代替真实触屏手感。

旧基线在新 AA、新 UI 和当前业务偏好落地前采集，缺失的条件不从当前 Editor 补填。它可用于历史热点、分配链路及异常窗口归因，不能与最新采样直接构成严格同条件整体收益对照。每场以正式采集元数据记录实际分辨率、renderScale、MSAA / 原生 AA、后处理、VSync、帧率、音乐静音、业务与公共设置；仅有相同分辨率不足以证明条件相同。

按用户最新要求，本次不回切整套旧源码重采基线。以下数字描述当前实现；未取得严格同条件配对证据，因此不填写整体提速百分比。旧报告仍用于追溯已修的分配调用链和历史峰刺。

## 1080p 正常驾驶

四章各录两次，每场至少 60 秒并完成一圈；合计 57 段、56,981 个正式分析帧，所有段均为 completed、dropped=0，报告源文件与采集元数据逐一核对。分位数按全部原始帧最近秩计算，不平均各段分位数。GC 列是 **Editor + PlayMode 测试驱动 + 游戏** 的合计，不能当成玩家运行时分配。

| 章节 | 录制秒数 | 帧数 | P50 / P95 / P99 (ms) | 超过 16.67 ms | GC B/帧 |
|---|---:|---:|---:|---:|---:|
| 雏菊草原 | 126.6 | 13,977 | 8.65 / 11.64 / 17.29 | 1.15% | 410.8 |
| 博斯普鲁斯夜景 | 122.8 | 14,028 | 8.42 / 10.71 / 17.31 | 1.08% | 290.3 |
| 冰川通道 | 123.7 | 13,946 | 8.44 / 11.26 / 19.12 | 1.30% | 351.1 |
| 书写桌面 | 127.4 | 15,030 | 8.19 / 10.44 / 15.10 | 0.75% | 330.6 |

主线程 `KagitKartWorld.Update` 的平均 Self 为 0.27～0.35 ms/帧、Calls 为 1/帧；`LateUpdate` 为 0.49～0.71 ms/帧。海峡样本的 `EditorLoop` Self 约 2.87 ms/帧，`Profiler.FlushMemoryCounters` 约 0.32 ms/帧。父子 Total 及不同线程的时间不能相加，EditorLoop 也不能当成 Player 成本。最初观察到的 `Update() 0.290 ms` 与本次草原约 0.29 ms/帧一致，它本身并不足以解释整帧卡顿。

两段独立 GC 调用栈诊断共 1,913 帧、19.3 秒，`World.Update` 合计 3,682 B、48 次分配，属于道具创建、首次缓存增长及事件文案，并非每帧发生。`LateUpdate` 的稳定约 72 B/帧可追到 Unity Editor 内 `TMP_Text.InternalTextBackingArrayToString()`，用于逐帧准确显示计时；测试运行器的断言和反射也产生持续分配。普通窗口草原的总量 410.8 B/帧包含测试驱动、Editor/TMP 和冷路径；其中 `World.Update` 平均约 102 B/帧，主要集中在少数首用帧，而非均匀散在每帧。不能据此宣称整个 Editor 或 Player 全流程绝对 0 B/帧；项目已定位且可等价清理的持续热路径分配已修，新的 Player 分配上界仍待真机验证。

## 4K 补充与异常帧

草原和夜景各有约 20 秒短窗口，未跑完整圈。草原 1,211 帧的 P50/P95/P99 为 15.77/26.94/35.03 ms；夜景 1,183 帧为 16.06/25.45/34.76 ms。`GfxDeviceD3D12.WaitForLastPresentation.WaitForGPU` 的 Self 分别约 6.93/7.70 ms/帧，说明 4K 有明显的 GPU/呈现等待；它不能单独判定哪一个 Shader Pass 最贵，也不能靠 CPU 修改承诺 4K 稳定 60 帧。

- 冰川第一次第 0 段第 0 帧是本轮最大值 189.24 ms、529 B GC；后两帧 8.99/9.14 ms。原始样本有 175.06 ms 处于 `Profiler.SessionMetadata` 与 `PlayerLoop` 之间的未归属时间，`World.Update` 只有 0.57 ms Self，属于录制段首/Editor 时间，不能算作业务计算回归。
- 冰川第一次第 2 段第 593 帧为 58.45 ms、459 B GC；前后帧 12.18/13.74 ms，GC 同为 459 B。`World.Update` Self 45.16 ms，未采到更细业务子样本，保留为孤立且未归因的更新峰刺。
- 冰川第二次第 0 段第 23 帧为 52.14 ms、122 B GC；前后帧 12.71/7.60 ms。原始样本有 `GC.Collect` Self 21.30 ms，父级增量回收 Total 42.59 ms；该帧本身的少量分配不能说明是谁累积触发回收，Editor/TMP 与测试驱动均在同一录制中分配。
- 草原第二次第 2 段第 43 帧为 23.78 ms、658,720 B GC；前一帧 7.97 ms/122 B，后一帧 8.96 ms/316 B。原始样本内 `World.Update` Total 13.42 ms，并出现大量 Mono JIT、Editor 材质处理和网格首次注册。该冷资源窗口与 GC 同时出现，但没有证据表明发生了 GC 回收；不以预先常驻全部资源的内存代价掩盖这次首用。
- 夜景第二次第 2 段第 692 帧为 36.37 ms、40 B GC；前后帧分别 8.29/10.77 ms。`World.Update` Self 27.62 ms，当前未采到更细的业务子样本，且另一轮没有同型可重复帧；归因保留为单帧业务计算或原生调用未细分，不能称为 GC 峰刺。
- 旧诊断第 275 帧的 36.44 ms 中曾有 `File.Read` 15.91 ms，推动普通 SFX 预热和 boost PCM 双缓冲复用。本次短诊断未重现同一路径；末圈/结算音乐首次解码及 DSP Voice 整块锁仍是事件风险，须在完整赛程或 Player 记录中证实后再决定是否用更多常驻内存换取预热。

## 改动、验证与边界

已修复四章灯光输入重复 `1/π`、纸纹像素尺度和场景默认 AA；仅在卡丁车相机作用域停用确认无消费者的 SSAO 与 Opaque Color 复制，保留纸印全屏 Pass 自身的颜色复制、FinalDepthPass 和公共画质设置。停用前后的四章像素检查各比较 8,294,400 字节、差异均为 0；该检查在最后的 AA 调整前完成，最终画面另按截图核对。输入与规则路径消除了重复临时字符串、枚举和通知；纸景恢复静止休眠与脏更新；音效样本和 boost 音频缓冲复用，Engine 控制参数与 DSP 大块处理解耦。每项依据和操作入口见[编辑器性能维护](editor-performance.md)、[音频维护](audio.md)及[来源迁移](source-migration.md)。

正式工具已完成录制、停止、保存、加载、CPU/GC 分析、报告比较、用户接管及损坏文件回滚的定向验证；比较工具对旧/新诊断明确返回“条件不同”警告。另录制了菜单、起跑、倒计时、八种道具、救援、暂停、恢复及结算的 16 个独立事件窗口，保存在历史归档；它们早于最终 AA/UI 条件，未全部逐段重新分析。四章最终画面、设置选中态和触屏按键已看实际截图，相关既有 Input、Flux、场景、音频与功能定向测试通过；不把截图 FPS 数字用于帧率结论。一次性 Builder、探针与测试源码及其 `.meta` 共 14 个文件已删除，删除后的 Unity Editor 编译为 0 错误；未自动跑全量回归。

历史原始证据在 `history_owned_20261013.zip`，其 `.verified.json` 记录每项 SHA256 与 ZIP CRC；中断的 18 段旧采样隔离，未纳入正常比赛。当前 63 段原始文件和 63 份完整缓冲报告在 `current_owned_20261013.zip`，以对应校验清单和 `aggregated_report.json` 复算；63/63 份报告均覆盖所保存的完整帧范围。两次失焦留下的 9 段半场另在 `discarded_partial_capture.json` 登记后删除。用户原有 Profiler 缓冲备份单独保护。未执行独立 Player/IL2CPP、Android 真机及真实触屏/手柄验收；Editor 数据不能代替手机表现。
