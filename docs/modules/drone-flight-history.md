# DroneFlight 设计演进与决策记录

## 用途

本文只记录影响长期维护的改版原因、被替代方案和仍有效约束。当前实现以 [DroneFlight 模块说明](./drone-flight.md) 为准，具体操作以相关 runbook 为准。

## 2026-08-13：飞行仿真初版

提交 `5fa86eb` 建立了 DroneFlight Demo 岛、四个 Rotor 独立施力、PID、电机模型、相机、输入、遥测、吊挂原型和第一批自动化测试。

关键决策：

- 使用 Rigidbody 与四个真实施力点，不采用中心总推力动画方案。
- 飞控核心用可独立测试的数学类型承载，MonoBehaviour 负责与 Unity 物理桥接。
- Demo 从一开始同时维护模块文档、调参 runbook、Goal 和实施计划。

后来被替代：

- 早期 `DroneFlightDemoLauncher`、`DroneHudPresenter` 和单一原型抓钩不再是正式入口。
- 初版几何占位机体已被正式 FBX 与确定性 Builder 替代。

## 2026-08-14：试玩、六轴飞控与吊挂载荷重构

提交 `179ea30`、`d0b0fdf` 根据试玩反馈完善飞行体验，并重构物理抓斗、载荷交接、控制分配和自动载重调校。

关键决策：

- 控制链固定为输入整形、位置/速度、推力方向姿态、角速度 PID、物理控制分配、电机、四点施力。
- 额定载重影响动力调校，最大载荷倍率只影响抓斗门禁，两者不与 Cine/Normal/Sport 混用。
- 载荷质量按真实约束竖直拉力平滑进入飞控前馈，不在抓取瞬间直接加入完整质量。
- 释放载荷不清零速度或 RPM，让无人机按真实剩余电机转速短暂上浮并恢复。

后来被替代：

- 旧卷扬和单抓钩结构被短行程四爪抓斗替代。
- 飞控主动防摆不再由装备宿主提供；抓斗的摆动只由装备内部 Joint 限位和被动阻尼处理。

## 2026-08-15：正式机体与模块化装备

提交 `a359fa8` 引入正式 Blender/FBX 机体、六套 URP 材质、三级云台、真实起落架节点、独立抓斗/渔叉 Prefab 和三个成品机型；提交 `467634f` 将测试统一迁到项目标准测试程序集。

关键决策：

- `DronePrototype` 同时是共享飞行基础和纯无人机成品；装备机型是编辑期保存的 Prefab Variant。
- 运行时只选择并实例化成品 Prefab，不调用 Builder，也不动态拼装装备。
- FBX 导入节点的轴转换不能充当物理推力轴；物理推力固定使用机体根局部 `+Y`。
- UI 通过正式 UIManager 和强类型 ViewData 工作，生成的 `*Component.cs` 不手改。
- 所有自动化测试统一位于 `Assets/Scripts/Tests/EditMode|PlayMode/Demo/DroneFlight`。

## 2026-08-15：代码治理与迁移准备

本轮把机体同步装配从 SleepyDemos 场景事务中提取为纯 Unity/DroneFlight 协作者，将旋翼执行细节从飞控编排器中分离，并建立 Builder、测试共用的机器模型契约。

新增长期规则：

- 可迁移核心不能引用 UIManager、ResourceServices 或 GameSceneNavigator；这些依赖只允许出现在明确的宿主适配器中。
- 三套配置 Inspector 必须共用互斥语言状态，并保证所有字段、Tooltip 和错误诊断完整双语。
- 模型层级、轴向、材质槽和物理挂点只在 `DroneFlightModelContract` 定义；文档解释语义，测试执行门禁。
- 当前不承诺只复制两个目录即可零修改运行；迁移时按 [迁移 DroneFlight](../runbooks/migrate-drone-flight.md)替换宿主适配点。

## 2026-08-15：移除原型期兼容层

旧六爪抓钩、卷扬、软抓取、悬挂遥测、主动防摆入口和旧重置协调器已全部退出当前三机型链路，因此不再保留空实现组件或零值接口。腹部装备输入正式统一为 `DroneEquipmentInput`，当前场景、配置和三个成品 Prefab 直接使用新结构。

长期规则：Demo 阶段不维护已废弃序列化字段和类名的向后兼容。删除或重命名字段时同步更新 Builder、资产 YAML 和契约测试；历史原因只记录在本文，不留在运行时代码中。

## 2026-08-15：调试显示、万向抓斗与向下渔叉修正

- F2 从 Editor `OnGUI` 投影线改为无物理组件的世界空间 LineRenderer 箭头和 3D 标签，Game/Scene 共享显示。
- 起落架状态语义仍为 `0=放下、1=收起`，仅把 Builder 折叠方向改为契约中的 `-67°`，不修改飞控。
- 抓斗取消短行程和 J 操作，改为单根刚性吊臂加机腹万向节；吊臂属于底座复合刚体，锁定线性位移和轴向扭转，仅保留双轴被动摆动。
- 渔叉缩短到起落架净空内，发射轴改为机体局部 `-Y`；V 进入俯视鼠标瞄准，H 仅在有效射界发射，J/K 仍只改变真实绳长。

长期规则：装备不得写飞控目标姿态；抓斗不得增加链节刚体；停靠渔叉的可见结构与启用 Collider 不得低于脚底；Builder 生成的 MeshRenderer/LineRenderer 必须引用持久化材质资产。

## 2026-08-15：抓斗与渔叉可玩性收口

- 抓斗保留四个真实 HingeJoint 爪子，但取消容易失效的对向接触计数；闭爪时按底座下方捕获体积选择最近 `DronePayload`，并建立临时 FixedJoint。
- 四爪改为向下弯曲的两段式复合 Collider；张开时口径覆盖 `0.30 m` 演示载荷且保持起落架净空，闭合后向下、向内形成抓娃娃机式包围。
- 渔叉停靠态成为 Prefab 与运行时共同保证的硬状态：Kinematic、无重力、Collider 关闭、绳索隐藏，并持续跟随 Muzzle。
- 专用瞄准由机体上方俯视改为现有 `BellyCameraMount` 机腹视角；发射改用可直接调节的冲量，默认 `0.12 N·s`。

长期规则：爪子碰撞负责可见闭合效果，玩法抓取由临时 FixedJoint 保证可靠；释放不得清零载荷速度。渔叉未发射时不得依赖 Host 生命周期顺序防止坠落。

## 2026-08-15：装备质量、抓斗升降、镜头和调试可读性

- `BodyMassKilograms` 统一改为包含已安装装备的整机空载质量；抓斗动态部件保留正质量和真实关节反作用，但从主刚体等额扣除，附加设备质量对 HUD/F3 恒为零。渔叉弹体射出成为动态刚体时也从主刚体等额扣除；载荷仍以真实质量进入承载反馈。
- 抓斗恢复 J/K 操作，但语义仅为沿机体竖直方向移动万向节的 `ConnectedAnchor`，默认 `0–0.35 m`、`0.18 m/s`；不恢复多节链、卷扬刚体、主动防摆或速度清零。新增无物理组件的捕获辅助环和离地高度标签。
- CameraRig 按 Gimbal、ThirdPerson、Orbit、FixedForward、Belly/HarpoonAim 分别定义稳定规则，切换使用 `0.35 s` 过渡；外置镜头以自过滤 SphereCast 防穿模，且从不写机体 Rigidbody。HUD 改为精简布局，F1 控制完整操作说明。
- 渔叉解除后改用带重力补偿的受限 PD 回收，同时衰减径向/切向相对速度并向机体施加等量反作用；视觉绳由端点和目标长度确定，不再累计历史能量。
- F2 保留世界对象语义，增加非线性长度饱和、`22%` 屏幕短边上限、视口安全裁剪、像素恒定线宽/箭头以及带描边 TMP 标签；物理真值不被裁剪。

长期规则：不得把装备关节求解质量再次叠加到整机空载质量；镜头平滑只属于 Camera Transform；F2 的视觉裁剪不得改写遥测或飞控输入。

## 2026-08-15：可读性、直接控制与复合吊缆

- F2 的世界标签保持 TMP/LineRenderer 语义，但改为固定 `36` 基础字号加相机像素换算，并在同一渲染帧统一避开机体投影、画面边缘和其他标签；Auto Size 不再参与布局。
- 操作说明默认展开并拆成标题、飞行/档位、视角/系统和装备四个区域。选择机型后首个物理步直接进入未解锁的第三人称 Active，R 的电机解锁语义不变；F 仅兼容旧 Waiting 会话。
- 抓斗删除移动 ConnectedAnchor 与机腹刚性关节，改成无质量、无碰撞、只受拉的单根复合吊缆；J/K 以速度和加速度限制改变目标长度。吊缆不限制横向摆动，只在受力时施加小幅等量反向防扭扭矩。
- 渔叉玩法参数和物理链保持不变。视觉绳从 FixedUpdate 解耦，由独立组件在 LateUpdate 读取插值端点；端点逐帧精确贴合，只平滑中段下垂并以滞回消除绷紧阈值闪烁。

长期规则：可读性缩放只改变显示；玩法选择不得隐式解锁电机；抓斗视觉绳不得复用渔叉组件；渔叉视觉刷新不得反向写入目标绳长、张力或回收状态。

## 2026-08-15：撤回复合吊缆并固定机腹受力点

- 复合吊缆在仅 `0.05 kg` 的抓斗关节求解质量上使用高弹性、高阻尼与防扭矩，物理时间尺度接近或短于固定步长，实机验收出现底座和四爪高速分离。该试验方案被完整撤回，不再作为当前实现。
- 抓斗恢复上一提交的 ConfigurableJoint、单根刚性 `GrappleArm`、四个 HingeJoint 和载荷 FixedJoint。为修复下放时容易掀翻，机体侧 `ConnectedAnchor` 永久固定在 `BellyEquipmentMount`；J/K 改为平滑改变抓斗侧 `anchor.y` 与伸缩套筒长度，避免把反作用点下移形成额外力臂。
- 渔叉发射、命中、张力、收放与回收参数保持不变。停靠态视觉绳增加渲染帧级兜底：强制禁用 LineRenderer、清空旧顶点和下垂缓存，防止 Hot Reload、重启用或生命周期时序暴露上一条曲线。

长期规则：抓斗升降不得移动机体侧受力点；轻质量关节体不得直接使用未经固定步长稳定性验证的高刚度显式弹簧与防扭矩；停靠态渔叉绳必须同时满足 Renderer 禁用和 `positionCount = 0`。

## 2026-08-15：伸缩吊臂视觉轴与停靠弹体渲染同步

- 抓斗升降物理仍使用固定机腹 ConnectedAnchor 和抓斗侧可变 Anchor；仅修正视觉套筒。`LiftSleeveVisual` 改为 `GrappleBase` 子节点，沿底座局部 `+Y` 从固定吊臂顶端延伸到 Joint Anchor，因此会与抓斗一起摆动，不再沿机体竖直轴脱节。
- 渔叉停靠弹体不再保留 Rigidbody 插值。Stowed 状态由 FixedUpdate 维持 Kinematic/无重力/无碰撞，LateUpdate 再贴合当前 Muzzle 的渲染姿态；发射时恢复 Interpolate。绳索视觉和全部玩法参数保持不变。

长期规则：装备的伸缩视觉必须与真实约束轴一致；独立 Kinematic 停靠物若必须逐帧贴合插值后的父结构，不得再叠加自身 Rigidbody 插值造成双重延迟。

## 2026-08-15：云台模型光轴校准

- 正式模型的 `CameraBody` 可见镜面朝节点本地 `-Z`，此前 CameraRig 却从 `GimbalPitch +Z` 出图，导致偏航后模型与画面方向互为相反方向。
- Gimbal 输出改为使用 `CameraBody` 的位置与本地 `-Z` 光轴；Yaw/Pitch 机械节点、输入角度、世界地平线稳定和其他镜头模式保持不变。

长期规则：机械层级轴与可见镜头光轴必须分别建模；CameraRig 不得绕过 `CameraBody` 直接从 `GimbalPitch.forward` 推断正式镜头正面。

## 始终有效的禁区

- 不用中心总推力替代四个 Rotor，不用高阻尼掩盖振荡。
- 不因视觉换皮移动施力点、挂点或 Collider 契约。
- 不在运行时动态重建正式机体或装备。
- 不直接修改生成 View Component，不让 Core 反向依赖 Hotfix。
- 不把静态检查当作 Unity 编译、Prefab 引用、物理行为或视觉验收。
